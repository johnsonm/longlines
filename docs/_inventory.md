## Disagreements between code and older docs or copy

The pages follow the code in each case.

1. The DX Cluster catalog copy says "Not in Stats" (`web/src/sources/sources.ts`), but Stats counts
   DX Cluster in the world map and the hourly chart.
2. The RBN catalog `desc` says "CW and digital skimmer spots"; only CW and RTTY are read (port
   7000).
3. The Failing banner on Destinations says "Check the URL" for push destinations too, which have no
   URL.
4. The goal edit page says "Add as many requirements as you like." The limit is 10.
5. The goal page's "since you connected the relay" uses the first logged contact received, not the
   pairing time. Its relay "Connected" chip means a contact arrived in the last 7 days.
6. "States and bands never need a look" (goal page) has one exception: a contact at two parks in
   different states takes its state from the review.
7. The ended-goal banner says it "no longer counts new contacts", but a contact dated inside the
   window and posted late still counts.
8. The goal band picker offers 13 bands; SQL accepts 25.
9. The relay tokens card uses "Connected" twice: the column is the pairing date, the chip means the
   spots stream is open now.
10. The API tokens page's "API docs" button goes to `docs/API.md` on GitHub, not to
    docs.longlines.io, and its intro omits goals.
11. The landing page's "Send it anywhere" step lists only Discord and Webhook.
12. `docs/WEBHOOKS.md` says one-request-per-spot webhooks get "about 50 spots a minute"; the code's
    budget is 1,000 a minute with 5 spots per claim, and the real rate depends on the sender's
    cycle. The pages don't quote a figure.
13. The push design spec's Copy section still describes a summary notification and a fixed 15-minute
    TTL; neither exists now.
14. CLAUDE.md says every callsign the web shows links to `/call/<base>`; profile "Heard by", "Also
    heard as", "Recent spots" and the reference page's Spotter column are plain text.
15. The heat map period is "Past 12 months" on callsign profiles and "Past 365 days" on reference
    pages, for the same window.
16. The Local DX cluster editor's title and save button differ from the other three editors ("Add
    destination" title, "Save destination" when new).

## Open questions

1. **Hiding a profile.** The "To have this page hidden, email …" line appears only when the build
   sets `VITE_CONTACT_EMAIL`. Is it set in production, and what address should the docs give?
2. **Relay app, checked by hand.** The relay pages (`relay/*`) were checked against
   `sonyccd/longlines-relay` at cd60f2c. Its own docs list facts still to confirm by hand: real
   DXLog.net and MacLoggerDX packets, which exchange field N1MM fills with the state outside
   Sweepstakes, and whether N1MM Logger+ answers the cluster's `login:` by itself and puts the test
   spot in its bandmap. Many relay strings are marked "Invented" in its `src/copy.ts`; if they are
   reworded, the docs need the same change.
3. **Google-only accounts and passwords.** The Password card asks for a current password these
   accounts don't have. The account page suggests "Forgot your password?"; untested.
4. **PSK.** The "PSK" mode choice misses spots stored as PSK31 or PSK63. Intended?
5. **Disabled destinations.** A connection whose destinations are all disabled still shows its
   switch on and "N of the last M spots passed", but sends nothing.
6. **Repeat window by call as spotted.** K4ABC and K4ABC/P are separate stations for "Repeat spots
   for the same station". Intended?
7. **Group delete has no confirmation**, unlike connections, destinations and goals.
8. **Group "Get alerts" is hidden on phones** on the group page header (it is on the list card).
9. **Hidden members in group counts.** The owner's header counts hidden members; statistics don't.
10. **Production DX Cluster node and APRS-IS.** The default node is `dxc.hamserve.uk:7300` but can
    be overridden; APRS-IS needs `APRS_LOGIN_CALL`. Neither is visible in the repo.
11. **Relay with spots permission only.** A v2 relay can pair with `spots:read` alone; its contacts
    would be refused. The current relay always asks for both scopes (`SCOPES` in its
    `upstream/client.rs`), and the approval page grants what was asked, so only another client could
    do this.
12. **Approved but never claimed.** If the relay never picks up an approved pairing within 10
    minutes, the user saw "Relay connected" but no relay exists. Worth a troubleshooting line once
    the relay's behavior is known.
13. **Supported push browsers.** The code checks for web push support, not browser names or iOS
    versions; the push spec says iOS 16.4+. The push page names browsers without a version.
14. **Canadian licenses.** ISED import is designed but not built. Profiles say FCC only.
